## 운영 오류와 신뢰성

### Telegram 장애

9월 3일 `getUpdates` 장애 중 거래 사이클 오류 보고 전송도 실패했다. 이 예외가
`_run_cycle`에서 다시 빠져나와 `_drain_finished_cycle`, 스케줄러, 메인 루프를
차례로 종료했고 systemd가 서비스를 한 번 재시작했다. 빈 문자열 예외 때문에
Telegram 실패 원장 3건의 `error`도 비어 있었다.

- 백그라운드 알림 실패는 형식과 종류만 경고로 남기고 사이클을 종료하지 않는다.
- 완료 task의 예상 밖 예외와 스케줄러 한 회차 예외를 각각 격리한다.
- 빈 예외도 `TimeoutError` 같은 클래스 이름을 DB와 재발생 오류에 보존한다.
- 시작 시 Git 커밋, dirty 여부, 국장·미장 policy id를 journald, Telegram,
  runtime state에 남긴다. 미커밋 코드가 재시작으로 활성화되는 상황을 식별할 수 있다.

### 휴장 상태 오표시

9월 7일 13:30 UTC에 실제 Nasdaq은 노동절 휴장이었지만 제어기가 시간대만 보고
`from=both_closed to=us_regular`을 보냈다. 거래 엔진은 휴장 검사를 별도로 거쳐
주문하지 않았으므로 주문 안전 문제는 없었지만 운영 상태가 틀렸다. 상태 알림에도

다음 사이클에 재시도한다.
